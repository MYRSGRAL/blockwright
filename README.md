# Blockwright — компактные блок-схемы C++

Форк [CodedSplash/blockwright](https://github.com/CodedSplash/blockwright): исходный C++ преобразуется в чёрно-белую учебную схему, SVG/PNG и автономный браузерный редактор. Интерфейс — обычный JavaScript; сервер и сетевые сервисы не нужны.

## Запуск

Python 3.12 или новее. Парсеры для Windows x64 и Linux x86-64 включены в репозиторий. Для точных размеров текста и PNG через Chromium установите зависимости в виртуальное окружение:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m blockwright программа.cpp -o outputs/схемы --no-ui --png 2 --open
```

В Windows используйте `.venv\Scripts\python.exe`. При запуске `python -m blockwright` без аргументов открывается выбор файлов в терминале.

## Готовая схема

Учебный режим включён по умолчанию: скрываются простые объявления без действий, распознанная техническая обвязка ввода, объединяются безопасные инициализации и соседние выводы значений. Сохраняются алгоритмические условия, вычисления, побочные эффекты и результат возврата. Ввод и вывод различаются по синтаксическому дереву, а не по подписи блока.

Объявления без явно заданного значения (`int n, i;`, `int *p;`, `string line;`) не занимают блок. Присваивания и явные значения (`c = 100`, `k = 0`) остаются. Создание неизвестного объекта с конструктором сохраняется как действие.

Блок ввода включает приглашение, чтение и распознанную проверку корректности с сообщениями об ошибках. Для массива используются `Ввод n`, затем `Ввод a[n]`, где `n` — число элементов. Поддерживаются прямой `cin`, чтение внутри условия, проверка после чтения, `getline`/`istringstream`, границы количества и поэлементное чтение циклами `for`/`while`. Повторно используемые буферы скрываются лишь при отсутствии других применений; вызовы, изменение переменных в сообщениях и нестандартные действия сохраняются подробно. Цикл чтения сохраняется, если его счётчик нужен последующему коду.

Несколько размеров показываются как `Ввод n, m`, а чтение прямоугольной матрицы — как `Ввод a[n][m]`. Служебные сбросы строкового потока и проверки разделителей входят в ввод, если весь протокол распознан. Вложенные циклы вычислений над матрицей остаются на схеме.

Чистый цикл печати массива заменяется на `Вывод a[n]`; соседний вывод количества объединяется в `Вывод n, a[n]`. Сообщение «пустой» при нулевом размере относится к тому же выводу. Отдельные пробелы и переводы строки не создают пустой блок вывода. Циклы обработки массива и алгоритмические условия сохраняются. Для дробных границ, конфликтующих типов, массивов объектов и `volatile` используется подробное представление.

По умолчанию `--checks hide` показывает основной алгоритм для корректных входных данных: распознанные проверки чтения и `isfinite` с ветками статического сообщения и завершения `main` скрываются. Сам ввод сохраняется. Дополнительные действия в ветке ошибки, вычисляемый код возврата и проверки в других функциях сохраняются. `--checks show` возвращает служебные проверки; `--detail full` всегда показывает подробную программу.

Отдельные служебные вызовы `SetConsoleCP`, `SetConsoleOutputCP`, `setlocale`, `ios::sync_with_stdio` и `cin/cout/cerr/clog.tie` с распознанными константными аргументами скрываются в учебной схеме. Вызовы с вычисляемыми аргументами, проверкой результата и пользовательскими одноимёнными функциями сохраняются. Полный режим `--detail full` показывает и настройку среды.

Обычный цикл повторного ввода с `cin.clear()` и `cin.ignore(10000, '\n')` в `main` показывается одним вводом; при `--checks show` — как ввод, проверка ошибки, сообщение и повтор. Дополнительные действия и нестандартная очистка сохраняются подробно. У безусловного цикла нет фиктивного ромба `true` и ветки «Нет». Отдельный `system("pause")` скрывается как служебная пауза завершения; другие команды и проверка результата сохраняются. Переопределённые в исходном файле макросами имена не используются для сокращений; внешние заголовки не раскрываются препроцессором.

В учебных подписях `(int)` заменяется на «целая часть(...)», означающую усечение к нулю. Сама формула сохраняется: удаление приведения изменило бы результат вычисления, особенно для отрицательных чисел.

Основной путь вертикальный. У обычного блока вход сверху и выход снизу; у ромба выходы вниз и вправо. У соединителей обратных межстраничных переходов вход слева и выход справа, чтобы сохранить допустимые направления п.4.2.4 ГОСТ. Ранние обычные возвраты сходятся к общему концу; исключения сохраняют отдельное завершение. Выход из волнистой фигуры вычисляется по кривой. Размер шрифта схемы — 11 пт, подписей ветвей — 9 пт; Times New Roman с резервным Liberation Serif.

Переносы подбираются под ширину отчёта без масштабирования шрифта. Область по умолчанию — 605×926 CSS px при 96 dpi, приблизительно 160×245 мм для A4 с полями. Сохраняется непрерывная схема; для высокой схемы дополнительно создаются файлы `__p01.svg`, `__p02.svg` и соответствующие страницы альбома. Парные соединители обозначают продолжение одного перехода.

```sh
python -m blockwright программа.cpp --notation course --no-ui
python -m blockwright программа.cpp --notation gost --no-ui
python -m blockwright программа.cpp --detail full --no-ui
python -m blockwright программа.cpp --page-height 0 --no-ui
```

`course` — профиль методички: ввод параллелограммом, вывод с одной плавной волной по предоставленному образцу. `gost` — обозначения схемы программы: ввод и вывод общим параллелограммом «Данные». [ГОСТ 19.701-90](https://rosgosts.ru/file/gost/01/080/gost_19.701-90.pdf): пп.4.1.2–4.1.4, 4.2.1–4.2.4 и раздел 5. Волнистый вывод — требование методички, а размер шрифта и A4 — параметры этого форка.

## Редактор и экспорт

Откройте `index.html` из папки результата. Можно перемещать блоки, менять подписи, отменять изменения, добавлять отдельные ввод и вывод, сохранять/открывать проект JSON, экспортировать SVG и PNG. Тема интерфейса не меняет чёрно-белые цвета схемы. Заголовок при экспорте включается отдельным флажком.

Ручные правки в браузере привязаны к данным конкретной генерации. Если модель схемы изменилась, альбом показывает новый результат, а не старую сохранённую версию. Предыдущие записи сохраняются отдельно; повторное открытие той же версии восстанавливает её правки.

PNG из командной строки использует `rsvg-convert`, если он установлен, либо Chromium/Chrome/Edge и Pillow. Путь к браузеру можно задать переменной `BLOCKWRIGHT_BROWSER`. Ошибка экспорта возвращает ненулевой код; старый PNG не считается новым успешным результатом.

## Границы автоматизации

Неизвестные конструкции сохраняются исходным выражением. Сложный протокол чтения с циклами и повторным использованием буфера может остаться подробным. Это синтаксический анализ, не замена проверке C++ компилятором. Синтаксические ошибки блокируют построение схемы этого файла. Очень широкая конструкция, которую невозможно разместить переносами, сохраняется с естественным размером и явным сообщением; страницы автоматически разделяются по высоте.

Подробный режим сохраняет исходные выражения и прежние способы представления конструкций. Для учебных схем предпочтителен включённый по умолчанию явный цикл с условием и шагом.

## Проверки

```sh
python -m unittest discover -s tests -v
ruff check blockwright tests tools/vendor.py build.py
ruff format --check blockwright tests tools/vendor.py build.py
```

Контрольный корпус — четыре лабораторные C++ в `tests/fixtures/study/`. Тесты проверяют сокращения и их границы, ветви и возвраты, порты, геометрию и страницы, CLI, SVG/PNG и браузерные контуры.
