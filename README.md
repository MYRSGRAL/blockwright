# Blockwright — компактные блок-схемы C++

Форк [CodedSplash/blockwright](https://github.com/CodedSplash/blockwright): исходный C++ преобразуется в чёрно-белую учебную схему, SVG/PNG и автономный браузерный редактор. Интерфейс — обычный JavaScript; сервер и сетевые сервисы не нужны.

## Запуск

Python 3.12 или новее. Парсеры для Windows x64 и Linux x86-64 включены в репозиторий. Для точных размеров текста и PNG через Chromium установите зависимости в виртуальное окружение:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m blockwright программа.cpp -o outputs/схемы --no-ui --png 2 --open
```

В Windows используйте `.venv\Scripts\python.exe`. При запуске `python -m blockwright` без аргументов открывается выбор файлов в терминале.

## Готовая схема

По умолчанию строится непрерывная учебная схема с краткими обозначениями: ввод и вывод подписываются переменными, присваивания группируются по строкам, а канонические циклы `for` показываются шестиугольниками с возвратом в левую грань. В этом режиме скрываются простые объявления без действий, распознанная техническая обвязка ввода, объединяются безопасные инициализации и соседние выводы значений. Сохраняются алгоритмические условия, вычисления, побочные эффекты и результат возврата. Ввод и вывод различаются по синтаксическому дереву, а не по подписи блока.

Объявления без явно заданного значения (`int n, i;`, `int *p;`, `string line;`) не занимают блок. Присваивания и явные значения (`c = 100`, `k = 0`) остаются. Создание неизвестного объекта с конструктором сохраняется как действие.

Блок ввода включает приглашение, чтение и распознанную проверку корректности с сообщениями об ошибках. Для массива используются `n`, затем `a[n]`, где `n` — число элементов. Поддерживаются прямой `cin`, чтение внутри условия, проверка после чтения, `getline`/`istringstream`, границы количества и поэлементное чтение циклами `for`/`while`. Повторно используемые буферы скрываются лишь при отсутствии других применений; вызовы, изменение переменных в сообщениях и нестандартные действия сохраняются подробно. Цикл чтения сохраняется, если его счётчик нужен последующему коду. Повторные попытки через `getline`/`istringstream` также входят в один ввод; интерактивная команда выхода по `#` сохраняется отдельно от проверки корректности символа.

Несколько размеров показываются как `n, m`, а чтение прямоугольной матрицы — как `a[n][m]`. Служебные сбросы строкового потока и проверки разделителей входят в ввод, если весь протокол распознан. Чистая печать массива или матрицы показывается одним выводом, включая нумерованные элементы. Техническое выделение памяти примитивных динамических массивов не занимает блок, если размерности не имеют побочных эффектов, а инициализаторы и placement-аргументы отсутствуют. Вложенные циклы вычислений над матрицей остаются на схеме.

Для текстового ввода `getline` распознанные проверки чтения, пустоты и длины строки относятся к блоку ввода. Проверка отсутствия слов скрывается только для подтверждённого счётчика прочитанных слов. Сам перебор слов и вычисления сохраняются; создание стандартного строкового потока показывается действием `iss = text` без типа C++.

Чистый цикл печати массива заменяется на `a[n]`; соседний вывод количества объединяется в `n, a[n]`. Сообщение «пустой» при нулевом размере относится к тому же выводу. Отдельные пробелы и переводы строки не создают пустой блок вывода. Циклы обработки массива и алгоритмические условия сохраняются. Для дробных границ, конфликтующих типов, массивов объектов и `volatile` используется подробное представление.

По умолчанию `--checks hide` показывает основной алгоритм для корректных входных данных: распознанные проверки чтения и `isfinite` с ветками статического сообщения и завершения `main` скрываются. Сам ввод сохраняется. Дополнительные действия в ветке ошибки, вычисляемый код возврата и проверки в других функциях сохраняются. `--checks show` возвращает служебные проверки; `--detail full` всегда показывает подробную программу.

Отдельные служебные вызовы `SetConsoleCP`, `SetConsoleOutputCP`, `setlocale`, `ios::sync_with_stdio` и `cin/cout/cerr/clog.tie` с распознанными константными аргументами скрываются в учебной схеме. Вызовы с вычисляемыми аргументами, проверкой результата и пользовательскими одноимёнными функциями сохраняются. Полный режим `--detail full` показывает и настройку среды.

Обычный цикл повторного ввода с `cin.clear()` и `cin.ignore(10000, '\n')` в `main` показывается одним вводом; при `--checks show` — как ввод, проверка ошибки, сообщение и повтор. Дополнительные действия и нестандартная очистка сохраняются подробно. У безусловного цикла нет фиктивного ромба `true` и ветки «Нет». Отдельные `system("pause")` и `system("pause > nul")` скрываются как служебная пауза завершения; другие команды и проверка результата сохраняются. Переопределённые в исходном файле макросами имена не используются для сокращений; внешние заголовки не раскрываются препроцессором.

Русские исходники UTF-8/BOM, CP866 и CP1251 приводятся к UTF-8 перед разбором. Различение CP866 и CP1251 без метаданных эвристическое: короткие неоднозначные тексты могут потребовать сохранения в UTF-8.

Приглашения, оканчивающиеся двоеточием или вопросительным знаком, перед распознанным вводом входят в блок ввода, в том числе меню выбора способа заполнения. До трёх коротких соседних присваиваний числовых переменных и элементов массивов объединяются в один блок; порядок действий и временные переменные сохраняются. Вызовы и индексы с побочными эффектами остаются отдельными действиями.

Простые числовые `+=`, `-=`, `*=`, `/=` и `%=` показываются через явное присваивание. Индексы с вызовами, макросами или наблюдаемыми чтениями остаются в исходной форме.

В учебных подписях `(int)` заменяется на «целая часть(...)», означающую усечение к нулю. Сама формула сохраняется: удаление приведения изменило бы результат вычисления, особенно для отрицательных чисел.

Основной путь вертикальный. У обычного блока вход сверху и выход снизу; у ромба выходы вниз и вправо. У шестиугольника цикла первичный вход сверху, обратная стрелка входит слева, тело начинается снизу, а завершение выходит из правой грани. У соединителей обратных межстраничных переходов вход слева и выход справа, чтобы сохранить допустимые направления п.4.2.4 ГОСТ. Ранние обычные возвраты сходятся к общему концу; исключения сохраняют отдельное завершение. Выход из волнистой фигуры вычисляется по кривой. Размер шрифта схемы — 11 пт, подписей ветвей — 9 пт; Times New Roman с резервным Liberation Serif.

Переносы подбираются под ширину отчёта без масштабирования шрифта. Ширина по умолчанию — 605 CSS px при 96 dpi, приблизительно 160 мм; высота непрерывной схемы не ограничена. Для страниц A4 с полями можно задать область 605×926 CSS px. По умолчанию сохраняется одна непрерывная схема (`--page-height 0`); при явном выборе высоты страницы, например `--page-height 926`, дополнительно создаются файлы `__p01.svg`, `__p02.svg` и соответствующие страницы альбома. Парные соединители обозначают продолжение одного перехода.

```sh
python -m blockwright программа.cpp --no-ui
python -m blockwright программа.cpp --detail full --no-ui
python -m blockwright программа.cpp --page-height 0 --no-ui
```

Основное оформление — `--io-style symbols`: подписи ввода и вывода содержат переменные и массивы без слов «Ввод» и «Вывод», а соседние простые числовые присваивания объединяются в один блок с отдельной строкой для каждого действия. Чистое заполнение двумерной `int`-матрицы через `rand()%N-K` показывается как `a[m][n] = random(-K, N-1-K)`; вычислительные циклы сохраняются. Вычисляемые операнды вывода, включая номер строки, остаются на схеме. Литеральные сообщения без выводимых значений сохраняются текстом. Эти сокращения относятся к учебному режиму, полный режим сохраняет подробные выражения.

Обычный запуск уже создаёт непрерывную схему без межстраничных соединителей:

```sh
python -m blockwright программа.cpp --no-ui
```

Распознанный поэлементный выбор ручного или случайного заполнения статической `int`-матрицы сворачивается в одно условие с двумя ветвями. Совмещённые печать матрицы и накопление сумм в `long long[]` показываются как вывод матрицы и сохранённые циклы подсчёта. Дополнительные действия, изменяемые индексы, неизвестные типы и макросы оставляют подробную схему.

Ввод обозначается параллелограммом, вывод — блоком с одной плавной волной по методичке. Переключатель `--notation` удалён: из старых команд уберите `--notation gost` или `--notation course`. При открытии старых JSON-проектов вывод также рисуется с волной.

## Редактор и экспорт

Откройте `index.html` из папки результата. Можно перемещать блоки, менять подписи, отменять изменения, добавлять отдельные ввод и вывод, сохранять/открывать проект JSON, экспортировать SVG и PNG. Тема интерфейса не меняет чёрно-белые цвета схемы. Заголовок при экспорте включается отдельным флажком.

Ручные правки в браузере привязаны к данным конкретной генерации. Если модель схемы изменилась, альбом показывает новый результат, а не старую сохранённую версию. Предыдущие записи сохраняются отдельно; повторное открытие той же версии восстанавливает её правки.

PNG из командной строки использует `rsvg-convert`, если он установлен, либо Chromium/Chrome/Edge и Pillow. Путь к браузеру можно задать переменной `BLOCKWRIGHT_BROWSER`. Ошибка экспорта возвращает ненулевой код; старый PNG не считается новым успешным результатом.

## Границы автоматизации

Неизвестные конструкции сохраняются исходным выражением. Сложный протокол чтения с циклами и повторным использованием буфера может остаться подробным. Это синтаксический анализ, не замена проверке C++ компилятором. Синтаксические ошибки блокируют построение схемы этого файла. Очень широкая конструкция, которую невозможно разместить переносами, сохраняется с естественным размером и явным сообщением; при заданной высоте страницы разделяются автоматически.

Подробный режим сохраняет исходные выражения и прежние способы представления конструкций. По умолчанию канонические `for` и распознанные счётные `while` показываются шестиугольниками с полной записью начала, условия и шага: `j = 0; j < m; j++`. Для `while` начальное значение должно однозначно следовать из исходного кода; неизвестные или неоднозначные циклы остаются ромбами. Начальные присваивания и шаги `while` сохраняются на своих местах, чтобы не менять порядок действий и поведение `continue`. У шестиугольников нет подписей «Да/Нет»; у ромбов условий они сохраняются. `--for-style decision` включает отдельные условие и шаг. Прежние словесные подписи доступны через `--io-style pretty`.

python -m unittest discover -s tests -v
