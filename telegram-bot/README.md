# Telegram-бот Blockwright

Отдельный Go-модуль без сторонних зависимостей. Требуется Linux, Go 1.25+ для сборки и команда `blockwright` в `PATH` при запуске.

```sh
cd telegram-bot
go build -o blockwright-telegram .
# TELEGRAM_BOT_TOKEN должен быть передан через окружение.
./blockwright-telegram
```

Бот использует официальный Telegram Bot API с long polling; webhook для того же токена должен быть отключён. `/start` показывает инструкцию. Доступ открыт всем отправителям документов `.cpp`, `.cc`, `.cxx`; исходное имя не используется как локальный путь. Исходный C++ разбирается Blockwright и не компилируется и не исполняется.

В изолированном временном каталоге выполняется:

```sh
blockwright input.cpp --out <каталог>/output --no-ui --no-html \
  --for-style hexagon --detail study --checks hide --io-style symbols \
  --page-height 0 --png 2
```

Лимиты: вход 256 КиБ по метаданным и фактическим байтам, не более двух задач одновременно и одной на пользователя. При занятости запрос отклоняется без очереди. Полный цикл скачивания, построения и отправки ограничен 90 секундами; HTTP-запрос — 40 секундами. Результат — до 10 PNG общим размером до 20 МиБ, отправляемых последовательно через `sendDocument` без сжатия. Лимит результата проверяется после построения; размер временных файлов во время работы ограничивается ресурсами среды запуска.

Токен не передаётся в процесс Blockwright и не выводится в логи. Вывод CLI отбрасывается. SIGINT/SIGTERM отменяют запросы, завершают группу процессов обработчика и дожидаются очистки временных каталогов. API-ответы ограничены 1 МиБ; перенаправления HTTP запрещены. При ошибке отправки уже доставленные PNG не отзываются, автоматического повтора отправки нет.

После успеха, ошибки скачивания, построения или отправки, таймаута и отмены бот удаляет каталог задачи целиком, включая исходник и PNG. Для дочернего CLI `TMPDIR` и `HOME` указывают на этот каталог, а `XDG_CACHE_HOME` — на его подкаталог `cache`; Python bytecode отключён через `PYTHONDONTWRITEBYTECODE=1`. Окружение самого бота сохраняется, общие временные каталоги и чужие кэши не очищаются. Если ОС отказывает в удалении, обработка возвращает ошибку и журнал получает сообщение без пути и токена. Принудительное завершение через SIGKILL или сбой хоста не позволяют выполнить завершающую очистку.

Offset обновляется после принятия документа рабочей задачей или синхронного отказа. Очередь и offset находятся в памяти: перезапуск может потерять принятую задачу или повторно получить последнее обновление. Запускайте один экземпляр бота на токен; долговечная очередь в этот минимальный сервис не входит.

Проверки:

```sh
go test -race ./...
go vet ./...
```
