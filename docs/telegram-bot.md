# Telegram-бот в Docker

Публичный бот принимает `.cpp`, `.cc`, `.cxx` и возвращает блок-схемы PNG ×2
документами. `/start` показывает инструкцию. Для каждой распознанной функции
создаётся отдельная схема. Доступ открыт всем пользователям.

## Сборка и запуск

```sh
docker build -t blockwright-telegram:local .
read -rs 'TELEGRAM_BOT_TOKEN?Токен бота: '
export TELEGRAM_BOT_TOKEN
docker compose up -d --no-build
unset TELEGRAM_BOT_TOKEN
```

Пример ввода токена рассчитан на zsh. На сервере токен можно хранить в `.env`
рядом с Compose с правами `0600`, задав `TELEGRAM_BOT_TOKEN=...`.
Не добавляйте этот файл в Git и не отправляйте вывод `docker compose config`
или `docker inspect`: они могут раскрыть переменные окружения.
Для локального теста конфигурации используйте фиктивное значение токена.

Входящие порты не нужны: используется long polling к `api.telegram.org:443`.
Для одного токена запускайте один экземпляр; ранее настроенный webhook
следует отключить перед запуском polling.

```sh
docker compose logs --tail 50 bot
docker compose down
```

## Параметры и ограничения

```text
blockwright input.cpp --out <временная папка> --no-ui \
  --for-style hexagon --detail study --checks hide --io-style symbols \
  --page-height 0 --png 2 --no-html
```

Вход — до 256 КиБ, максимум две параллельные обработки и одна на пользователя.
На обработку выделяется 90 секунд. Результат — максимум 10 PNG общим размером
20 МиБ. При превышении лимитов бот сообщает об ошибке. C++ не запускается.
PNG формируется через librsvg; шрифт Liberation Serif установлен в образе.
Генератор ограничивает растр 100 миллионами пикселей: очень длинную программу
может потребоваться разделить на отдельные файлы.

Счётные `while` с известным начальным значением, простым сравнением и числовым
шагом получают полный заголовок шестиугольника: `i = 0; i < m; i++`.
Начальные значения и шаги также остаются на своих исходных местах:
оформление не переставляет действия и не меняет переходы `continue`.
Если начальное значение или шаг нельзя достоверно определить, `while`
сохраняет ромб условия. Обычные счётные `for` показывают три части своего
управляющего выражения.

Контейнер запускается с UID/GID 10001, без capabilities, с read-only корнем.
Временные данные находятся в `/tmp` контейнера (tmpfs 256 МиБ), очищаются
после запроса и не сохраняются между пересозданиями контейнера.
`TMPDIR`, `HOME` и `XDG_CACHE_HOME` генератора направлены в каталог запроса:
временные файлы и кэши удаляются вместе с ним, в том числе при ошибке,
таймауте или отмене. Ошибка удаления явно сообщается. SIGKILL или сбой хоста
не позволяют выполнить завершающую очистку; `/tmp` целиком временный.
Запись Python bytecode отключена, pip cache не включается в образ.
Лимиты Compose: 1 ГиБ RAM, 2 CPU, 64 процесса, ротация логов.

## Проверки

```sh
cd telegram-bot
go test -race ./...
go vet ./...
```

Без токена доступны тесты локального Telegram API и генерации внутри образа.
Реальную доставку `/start` и PNG нужно проверить с токеном при развёртывании.
Исходные файлы и токен проходят через инфраструктуру Telegram:
[официальная документация Bot API](https://core.telegram.org/bots/api).
