# Компактные учебные блок-схемы C++

Пользователь 26.10.2026 поручил создать полный GitHub-форк и выполнить согласованный в чате план. Результат: C++ → готовые чёрно-белые схемы для отчёта, ручная доводка необязательна. Реализация остаётся на Python и обычном JavaScript.

## Требования

- Входной язык продукта — C++; убрать остальные языки и их зависимости, сохранив используемое C++ наследование правил C внутри конфигурации.
- Учебный режим включён по умолчанию; подробный режим доступен для исходных выражений и диагностики. Не скрывать неизвестные конструкции или ошибки разбора.
- Убирать объявления без вычислений и распознанную техническую обвязку потоков. Сохранять инициализации, формулы, порядок действий, существенные условия, побочные эффекты.
- Сокращать только распознанные конструкции: ввод, вывод, ошибки ввода и проверку конечности числа. Лабораторная №2: «Ввод x», «Ошибка ввода?», инициализация power/sum/sign, явный цикл i=1 → i≤10? → тело → i=i+1, проверка конечности sum, два пути ошибок и один общий «Конец».
- Основной путь вертикальный; выходы ромба вниз и вправо; ошибки сбоку; возвраты по отдельным коридорам. Не накладывать фигуры, линии, подписи или наконечники; слияния имеют один общий последний участок. Для обратных участков обозначать направление.
- Профиль «методичка»: ввод — параллелограмм; вывод — документ с единственной плавной асимметричной волной по изображению пользователя. Профиль «ГОСТ»: ввод и вывод схемы программы — параллелограмм «Данные», согласно разделу 5 ГОСТ 19.701-90. Не представлять требование методички как требование ГОСТ.
- Times New Roman с метрически совместимым резервным шрифтом; чёрный текст и контуры, белый фон. Одинаковые правила в SVG генератора и браузера. Выход из документа лежит на волне, не на рамке.
- Сохранять результат возвращаемого выражения и побочные эффекты; обычные возвраты сводить к общему концу функции. Исключения не смешивать с нормальным завершением.
- Экспорт SVG/PNG; короткие лабораторные ориентированы на A4. Большие схемы автоматически разбиваются по высоте с парными соединителями и читаемым текстом, без потери переходов.
- Редактор, сохранение проекта, экспорт и маршрутизация после перемещения должны работать с новыми фигурами.

## Решения и основания

Сохраняем tree-sitter и структурную компоновку исходного проекта; улучшаем их отдельными проходами. Полный переход на Clang требует контекста компиляции и не нужен для первых учебных задач. Общий графовый движок пока не добавляем: существующий структурный алгоритм знает семантику циклов, а libavoid уже решает маршрутизацию в редакторе.

ГОСТ 19.701-90: п.1.2 — детализация; пп.3.1.1.1,3.1.2.4 — данные и документ; пп.3.2.1.1,3.2.2.4 — процесс и решение; пп.4.1.2–4.1.4 — расположение и читаемость; пп.4.2.1–4.2.4 — соединения; п.4.3.1.2 — подписи ветвей; раздел 5 — применимость символов.
